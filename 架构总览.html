电商售后 · Agent 方案

AI 客服与售后 Agent
从一句话到一笔可审计的退款

把「理解问题 → 查订单 → 判规则 → 出方案 → 等确认 → 走审批 → 执行」这条链路做成受控状态机。 模型负责理解与表达，代码负责判定与推进。

工具调用 10 个 业务规则 15 条 会话 12 态 / 退款 12 态 人工审批 L1 / L2 20 张表 · 21 个接口 原型 6 场景 / 13 断言全绿

主链路编排

蓝色节点是必须经过的不可跳过环节。方案与确认之间没有捷径，这是审计底线。

01
意图识别 + 槽位抽取

五类意图（订单 / 物流 / 退款 / FAQ / 其他），单轮最多追问一个槽位，上下文可继承订单号。

02
上下文装载 + 身份校验

订单快照、物流快照、会员等级、风控标签、适用规则版本；手机尾号不符不披露任何订单信息。

03
工具调用

get_order get_logistics check_refund_eligibility create_refund_draft；单轮上限 4 次，失败返回结构化错误而非异常。

04
规则引擎判定

15 条硬规则短路执行：状态 → 重复 → 类目 → 时效 → 金额 → 运费 → 审批分档，输出决策码。

05
方案卡 + 确认闸门

展示金额拆解、退回方式、到账时效；签发一次性 confirm_token（10 分钟）。 此时库里只有 DRAFT，没有任何资金动作。

06
执行分流

≤500 自动通过；500–2000 主管审批；>2000 财务审批；风控命中直接人工。

07
回写状态 + 通知 + 审计

状态事件、消息、工具调用、审批记录全部带 trace_id，任意一笔退款可 30 秒内回放。

双状态机

会话状态管「聊到哪一步」，退款单状态管「这笔钱走到哪一步」。两者解耦：会话 30 分钟过期，退款单可以活好几天。

会话状态机（12 态）

INIT→ AUTH_VERIFY→ INTENT_RESOLVED→ COLLECTING_SLOT⇄ TOOL_RUNNING→ PROPOSAL_PENDING→ EXECUTING→ PENDING_APPROVAL→ COMPLETED
ESCALATED ABORTED EXPIRED

退款单状态机（12 态）

DRAFT→ ELIGIBLE→ USER_CONFIRMED→ PENDING_APPROVAL→ APPROVED→ PROCESSING→ SUCCESS
REJECTED_BY_RULE REJECTED_BY_HUMAN CANCELLED / EXPIRED / FAILED
状态管理的三道保险：①转移表强校验，表里没有的 (state, event) 组合直接拒绝； ②version 乐观锁防并发覆盖；③每次跃迁写 agent_state_events，可回放、可归因。

业务规则（15 条，可配置 + 代码兜底）

规则在代码里，不在提示词里。运营可在 refund_policies 调整阈值，但判定永远由引擎做。

接口分层

对外接口不暴露决策细节，内部工具接口不面向终端，写操作必带幂等键。

层接口职责
对外POST /api/v1/agent/chatSSE 流式对话，事件：ack / state / tool_call / token / card / done
对外POST /api/v1/agent/confirm唯一能把退款单推进到 USER_CONFIRMED 的入口，校验 token
对外POST /api/v1/agent/handoff转人工，附结构化摘要，坐席无需重问
审批POST /api/v1/approvals/{no}/decision通过 / 驳回 / 转办 / 补材料，可改额并留痕
内部POST /internal/tools/refund/eligibility纯计算判定，返回决策码 + 金额 + 规则指纹
内部POST /internal/tools/refund/draft生成草稿与一次性令牌，不触发资金动作
回调POST /webhooks/payment-refund清结算结果，驱动 SUCCESS / FAILED

三条设计红线

不确认不落单

方案只写 DRAFT 并签发一次性令牌；模型没有权限直接提交退款。 "已提交"这句话只有在 token 校验通过后才说得出口。

规则在代码里

金额、时效、类目由引擎算，提示词只负责解释。 用户怎么说、模型怎么想，都改不了 BR 的判定结果。

一切可回放

每次工具调用、每次状态跃迁、每次审批都落库并带 trace_id。 客诉复盘能定位到"第几轮、哪个工具、哪条规则"。

原型验证结果

纯标准库 + SQLite，无第三方依赖，一条命令跑完 6 个场景。

交付与节奏

M1 · 第 2-3 周
MVP 闭环

5 个场景端到端，确认闸门 + L1 审批可用，mock 执行。

M2 · 第 4-5 周
完整能力

15 条规则 + 风控 + SLA 升级 + 降级 + 看板，60 条用例全绿。

M3 · 第 6 周
灰度上线

影子 → 5% → 20% → 全量；误退率 > 0.3% 自动回滚。
