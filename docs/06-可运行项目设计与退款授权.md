# 可运行项目设计与退款授权

## 1. 交付范围

依据压缩包中需求、接口、状态机和原型建设本地验收版。沿用退款规则引擎和工具层，增加浏览器工作台、HTTP 接口、持久化演示库、角色鉴权、模拟清结算、离线评测和实时影子对比。

| 模块 | 入口 | 职责 |
|---|---|---|
| 客户会话 | `frontend/` | 查订单、查物流、查看方案、显式确认或取消、转人工、查看退款事件 |
| 审批工作台 | `frontend/` | 主管和财务分档审批，主管登记模拟退回回执、回复工单 |
| 质量工作台 | `frontend/` | 逐轮回放、离线配对、实时样本盲评、授权与撤回、按 trace 审计 |
| HTTP 服务 | `prototype/server.py` | 请求校验、演示身份、业务事务、持久化模式开关 |
| 编排与业务 | `prototype/orchestrator.py`、`rules.py`、`tools.py` | 意图、槽位、状态迁移、金额规则、审批和执行 |
| 数据 | `prototype/db.py` | SQLite 演示订单、对话、退款、审批、工单、出站流水 |

本地版采用确定性意图识别、JSON 请求和同步模拟清结算，浏览器和接口同源。启动只要求 Python。压缩包里的 SSE、生产 OpenAPI、MySQL 和真实系统对接方案可用于后续部署设计。

## 2. 退款执行与授权

| 业务条件 | 确认后的状态 | 执行条件 |
|---|---|---|
| 未发货且可取消，金额 ≤ 500 元 | `APPROVED` | 系统模拟执行，成功后关闭订单 |
| 500 元 < 金额 ≤ 2000 元 | `PENDING_APPROVAL` | L1 客服主管通过 |
| 金额 > 2000 元 | `PENDING_APPROVAL` | L2 财务通过 |
| 已发货的退货退款 | `PENDING_RETURN` | 审批完成后，主管登记仓库验收或物流拦截回执 |
| 高风控、签收争议、部分退款 | 转人工 | 坐席核对事实、商品明细及数量 |
| 超期质量问题 | 补充凭证 | 人工核验材料 |

退货退款的回执是独立执行条件，免金额审批的退款也需要回执。档位按整数分计算，500 元和 2000 元均为所在档位的上界。按签收时间精确计算第七天的到期点。未发货取消退回原运费。附件的 BR-13 与原型在一般无理由退货的扣费条件上有分歧，本地版把自动扣回额设为零，生产扣费口径由运营确认并纳入版本化规则。

1. 方案绑定订单、用户、会话、金额、规则版本及确认凭证。草稿阶段的资金流水数为零。
2. 用户通过方案卡提交，服务端校验归属、一次性凭证和 10 分钟有效期，重新读取订单及规则。关键字段变化时，原方案失效，用户重新获取并确认。
3. 确认后的订单占用售后状态，阻止其他会话重复确认。业务写入通过 SQLite `BEGIN IMMEDIATE` 串行化，正式单序号和出站流水受数据库唯一约束。
4. 模拟执行复核订单剩余金额和执行状态，记录已确认、审批、核验、处理及完成事件。出站记录、订单退款累计与完成状态一次提交，审核和执行失败时事务回滚。
5. 质量运营可切换 `SHADOW` 与 `DELEGATED`。系统读取请求事务内的授权状态，撤回后暂停新的确认、审批触发与回执执行。授权日志保留操作者和时间。

## 3. 评测集与影子对比

`eval/dialogues.json` 包含 50 个合成场景，覆盖订单、物流、退款、政策咨询和人工转接。每个案例记录演示身份、对话或显式按钮事件及逐轮期望。边界场景另有订单金额、签收时间和风控夹具。评测检查动作、意图、规则码、金额、审批级别、退回核验、正式单数和出站流水数。

| 指标 | 结果 | 统计方式 |
|---|---:|---|
| 用例通过 | 50/50 | 所有已标注字段及护栏均满足 |
| 意图准确率 | 62/62 | 只统计标注意图的轮次 |
| 动作准确率 | 90/90 | 只统计标注动作的轮次 |
| 红线违规 | 0 | 包括未确认落单、无执行记录却承诺成功、资金数量异常 |
| 影子对比 | 17 一致、3 待复核、0 危险 / 20 组 | 同轮候选决策与模拟坐席基线配对 |

离线回放为每个案例建立独立内存库。三组差异来自催件是查物流还是转人工（CS-008）、3200 元应由哪一级审批（CS-017）、生鲜订单应规则拒绝还是人工分流（CS-020）。

实时影子模式保存当时的订单与风控快照、候选版本和内部退款建议。人工先根据该快照登记独立决定，保存后才能查看候选结果。同一订单的退款动作、金额、审批和退回条件逐项对比。应拒绝或转人工却生成方案、超额、审批降级、改变退款类型或跳过必要退回核验归为危险分歧。实时危险分歧阻止开启授权，发现时如已处于授权状态则自动撤回。

## 4. 验收和授权结论

**准予本地模拟授权，真实流量继续执行影子评估。** 本地开关采用意图 ≥ 92%、动作 ≥ 90%、红线违规为 0、危险分歧为 0。合成样本足以验收项目闭环，生产授权证据来自独立标注的真实样本和在线监测。

上线前先从脱敏历史工单抽取 500 条做意图与动作评测，另补充至少 50 条诱导、越权和过期重放用例。真实流量影子至少运行 3 天，按金额、类目、物流、风控和审批档分层。每条样本独立保留候选结果、人工决定、争议复核结论和版本。误退款率的分母使用本应允许候选自动执行的独立退款订单，分子为人工复核认定的误动作。用约 3000 笔零误退的独立样本，才可将单侧 95% 上界压至约 0.1%。

合格后从 5% 的低金额低风险流量开始，按 20%、50%、100% 逐级放量，每档检查退款额、误退、人工接管和出站对账。任一越权执行立即暂停，线上误退款率超过 0.3% 或日退款额环比增幅超过 200% 按原方案熔断。同一时间窗保持一致统计口径，日基数为零时由金额上限与人工复核兜底。

生产切换还需接入正式身份、可信物流回执、清结算异步消费与幂等回调、持续对账、SSE、模型评测及服务压测。当前审批 SLA 用于展示截止时间，审批转派、补件回传和超时调度仍待接入。

## 5. 本地接口

请求前缀为 `/api/v1`。`POST /login` 以演示账号换取 Bearer Token。JSON 响应包含 `ok`、`data`、`error`。所有金额内部使用整数分。授权、审批及用户确认通过独立的写接口进入事务。

| 方法与路径 | 当前用途 |
|---|---|
| `POST /agent/chat` | 输入 `text` 与可选的 `session_no`，返回会话消息及活动方案 |
| `POST /agent/confirm` | 输入 `session_no`、`refund_no`、`confirm_token`、`action` |
| `POST /agent/handoff` | 转人工，输入可选的 `session_no` |
| `GET /orders`、`/refunds`、`/refunds/{refund_no}` | 按当前客户读取订单、退款和事件 |
| `GET /agent/sessions`、`/agent/sessions/{session_no}` | 按当前客户列出并回看会话 |
| `GET /approvals`、`POST /approvals/{task_no}/decision` | 角色分档审批，通过或附理由驳回 |
| `GET /returns`、`POST /returns/{refund_no}/verify` | 主管登记模拟回执 |
| `GET /tickets`、`POST /tickets/{ticket_no}/reply` | 主管接管与人工回复 |
| `GET /quality/report`、`/quality/shadow` | 离线结果与实时采样 |
| `POST /quality/shadow/{id}/baseline` | 记录盲评基线并即时比对 |
| `GET /quality/authority`、`POST /quality/authority` | 授权状态及切换 |
| `GET /traces/{trace_id}` | 查看消息、工具调用、会话状态迁移和退款事件 |
