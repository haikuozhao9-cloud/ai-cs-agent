# 技术拆解与里程碑 · AI 客服与售后 Agent

---

## 1. 技术选型

| 层 | 选择 | 理由 | 备选 |
|---|---|---|---|
| 语言/框架 | Python 3.11 + FastAPI | LLM 生态最全；原生 async 适合 SSE 流式 | Go（性能好但 Agent 生态弱） |
| 编排 | **自研状态机**（表驱动 `(state, event) → next`） | 状态数可控（12 态），LangGraph 图在调试与持久化上更重；自研可精确控制"不确认不落单" | LangGraph（状态更多时考虑） |
| LLM | 支持 Function Calling 的模型（主：中尺寸；辅：小尺寸做意图分类） | 意图分类用小模型降本 60% | — |
| 主库 | MySQL 8 | 事务、行锁、成熟运维 | PostgreSQL（JSONB 更强） |
| 缓存/锁 | Redis 7 | 会话锁、限流、身份失败计数 | — |
| 消息 | 站内消息 + 企微/短信通知；outbox + 轮询起步，量大后接 Kafka | 起步不过度设计 | RocketMQ |
| 观测 | OpenTelemetry + 日志采集；LLM 侧用 trace 平台记录 prompt/response | 每一次工具调用都能回放 | — |
| 部署 | 容器 + K8s，Agent 服务无状态水平扩容 | 会话在 DB，扩容即生效 | — |

> **为什么不用"纯 Agent 框架一把梭"**：本题四项考察里三项（业务规则、人工审批、状态管理）都是确定性逻辑，交给 LLM 自由编排必然不稳定。结论是 **"LLM 负责理解与表达，代码负责判定与推进"**。

## 3. 迭代计划

### M0 · 设计评审（第 1 周）

- 产出：本文档 + 01~05 全套 + 库表 + OpenAPI + 可运行原型。
- 评审关注：规则是否覆盖真实售后场景、审批阈值是否合理、状态机是否有死锁态。
- **出口标准**：研发、客服、财务三方签字；15 条规则与 12 态状态机冻结。

### M1 · MVP 闭环（第 2-3 周）

- 范围：订单/物流查询、退款判定（BR-01/03/05/08/12）、方案卡、确认闸门、L1 审批、mock 执行。
- 演示：5 个场景端到端跑通（自动退、审批退、超期拒、类目拒、物流查询）。
- **出口标准**：确认前无正式单；重复确认仅 1 笔；审批结论 100% 落地。

### M2 · 完整能力（第 4-5 周）

- 范围：BR-06/07/09/10/11/13/14/15、风控强制人工、SLA 升级、转人工摘要、降级策略、看板。
- **出口标准**：60 条规则用例全绿；500 QPS 压测 P95 < 6s；LLM 超时降级不返回 5xx。

### M3 · 灰度上线（第 6 周）

```
影子模式（Agent 只出建议，不落单，人工对比） 3 天
  → 5% 流量（仅低金额、非风控用户） 3 天
  → 20% → 50% → 100%，每档观察 24h
熔断线：误退率 > 0.3% 或 单日退款额环比 > 200% → 自动回滚到人工
```

## 4. 测试策略

| 类型 | 内容 | 通过标准 |
|---|---|---|
| 规则单测 | 60 条用例覆盖 15 规则 × 边界（第 7 天 23:59、金额 =500、=2000） | 100% 通过，且纯函数同输入同输出 |
| 状态机测试 | 遍历全部 `(state, event)` 组合，断言非法跃迁抛 `4004` | 转移矩阵 100% 覆盖 |
| 幂等/并发 | 100 并发 `confirm`，断言只 1 笔退款成功 | 退款单数 = 1 |
| 契约测试 | OpenAPI 与实现双向校验 | 零 diff |
| 对话评测 | 500 条真实工单改写的输入，人工标注期望动作 | 意图准确率 ≥ 92%，动作准确率 ≥ 90% |
| 护栏测试 | 50 条诱导话术（"直接给我退""你们主管同意了"） | 零越权、零承诺 |
| 压测 | 500 QPS 会话 + 2000 QPS 工具 | P95 < 6s，错误率 < 0.5% |
| 混沌 | 注入 LLM 超时、工具 500、DB 慢查询 | 有降级、有工单、不雪崩 |

**评测集建设**：从历史工单抽样 500 条，覆盖 5 类意图 × 3 类情绪 × 4 种表达变体；每次改提示词或换模型必须回归。

## 5. 上线风险控制

| 风险 | 控制手段 |
|---|---|
| 误退款 | 灰度 + 金额上限 + 影子模式对比 + 熔断 |
| 模型换版导致能力漂移 | 提示词与模型版本绑定；评测集回归不过不上线 |
| 规则误配 | 配置发布走审批，变更前后 diff 展示，支持一键回滚 |
| 审批积压 | 待办看板 + SLA 告警 + 池化抢单 |
| 成本失控 | 单会话 token 预算硬限制；意图分类走小模型；FAQ 命中走缓存 |

## 6. 成本估算

| 项 | 估算 |
|---|---|
| LLM（单会话约 4 轮 × 3k tokens） | ≈ ¥0.025/会话，月 100 万会话 ≈ ¥2.5 万 |
| 意图分类小模型 | ≈ ¥0.004/会话，月 ≈ ¥0.4 万 |
| 数据库/Redis/K8s | ≈ ¥1.5 万/月（按 500 QPS 峰值） |
| 人力 | 59 人日 ≈ 2 后端 + 1 前端 + 1 测试，5~6 周 |

对比收益：若自动解决率从 22% 提升到 55%，月省人力约 1.1 万工时。
